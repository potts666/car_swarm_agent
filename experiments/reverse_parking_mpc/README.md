# 可倒车 MPC：单车门槛已通过，尚未复现策略性死锁

本轮优先验收项已完成：**同一停车地图、初态和目标下，允许倒车的新 MPC 独立完成 A 入库，3/3 次通过。** 24.8 s 首次满足终态，26.8 s 完成完整2 s停车保持。最终位置误差0.001406 m、朝向误差0.000630 rad（约0.036°）、速度0。实际控制区间每0.01 s采样，所有限值违背不超过1e-5验收容差，最小加垫车身静态 SAT 间距0.600 m。

随后，同模型/输入限制的顺序双车候选通过采样验证；冻结新基线后，三次独立双车 MPC 都在t=6.0 s拒绝 A 求解。此前两车均在运动，没有满足8 s持续停滞窗口。因此，本轮结论是**可倒车单车门槛已通过；已验证顺序双车方案的采样可行性；仍未复现 MPC 策略性死锁**。

上一轮 `../parking_conflict/` 的所有交付文件都保持原字节内容，已与其 delivery manifest 核对。没有修改旧 forward-only MPC，没有调整地图、车身、目标、安全间距或目标容差来获得上述结果。

## 新基线具体改变

新算法在 `mpc.py`，独立配置在 `config.json`。车辆4.5×1.8 m、后悬1 m、轴距2.7 m、单侧加垫0.1 m；转角±0.5 rad、加速度±1 m/s²、转角变化率≤1 rad/s、合加速度≤2 m/s²，邻车加垫SAT间距≥0.08 m、静态≥0.03 m。几何辅助函数被冻结且检查配置尺寸是否匹配，尺寸不匹配会拒绝运行。

速度为有符号[-1,1] m/s。参考不是两条插值路径：读取原候选的控制序列，使用**同一个0.1 s中点自行车模型**重新积分生成位置、朝向和有符号速度，控制时间格0.4 s、预测12步（4.8 s）。A参考负速度与倒车朝向演变一致；每个停止/换段周期显式记录 gear=0。目标函数使用有符号速度误差、姿态误差和参考控制偏差；优化初值首先取当前时域内的有符号控制参考，失败再试上一轮移位控制，不执行未接受结果。

参考方向也是规划模式：运动阶段约束速度方向，停止阶段及换挡前一周期末端施加速度为0的等式。停车等式是线性的，提供精确雅可比，避免有限差分在停车边界造成不稳定。最终输入实际违反容差、换挡未过零或车身采样冲突都会拒绝验收。转向是该离散模型的逐周期保持输入，转角速率按周期差分检查；没有宣称模拟了连续转向执行器。

所有目标权重、100次最大迭代、ftol=1e-7、差分步长1e-6、接受阈值1e-5都写在配置。SLSQP仍要求success和约束可接受同时成立，不会把“残差很小但求解失败”偷偷当成功。

单车最大仿真60 s、双车100 s，均在首次运行前配置；继承的 `criteria.duration_s=24` 是上一轮记录，不作为新 runner 时限，新时限明确来自 `acceptance`。目标容差仍是位置0.3 m、朝向10°、速度0.05 m/s，另要求完整2 s保持。记录时间是从0开始的相对仿真秒；继承epoch100可用于换算，但本离线runner不使用ROS时钟。

每轮重新优化、仅执行第一控制，再用实际模型状态重规划。单车实际第一控制与参考控制最大差异约0.0758，且独立测试给同一参考施加测量位姿偏差后，求解输出随之变化。这是模型闭环 MPC，不是播放参考路径，也不是实际车辆接口。

## 执行顺序和证据

1. 开发期先做A单车。停车子步索引错误导致首轮实际约束拒绝；修正索引后第二轮在停车换段拒绝求解；增加线性停车等式精确雅可比及明确差分步长后完成单车。还修正了保持计时：要求完整执行区间的所有检查点符合终态，避免仅数周期终点而少计一个区间。开发记录分别保留在 `development_attempt_*` 和 `development_results/`，不作为正式基线证据。
2. 最终源代码执行单车三次，记录在 `single_acceptance/`；每轮保存输入状态、参考状态/控制、warm start、输出控制、完整预测、求解尝试、实际下一状态和约束检查。CSV保存实际执行轨迹，metrics保存每轮目标距离、朝向、速度、位移、前后方向和求解时间。
3. `validate.py`重新验证“B安全等待、A先入库”。读取相同起始状态、相同车身/地图/物理限值和同一模型，用同一个 MPC residual evaluator检查参考采样约束和停止等式，并对每个实际控制区间做0.01 s加密检查。A/B目标时间24.8/56.0 s，完整时域58.0 s，最后2 s双车均符合终态；最小加垫车身间距1.400010 m，最小静态SAT间距0.600 m。完整控制、驾驶方向和带时间轨迹在 `witness_results/`。
4. `freeze.py`仅在3次单车和双车候选验证都通过、单车验收源文件哈希匹配时创建 `frozen_baseline.json`。冻结在首次双车独立运行之前。记录核心算法、runner、配置、参考及几何辅助文件的SHA256；双车入口检查哈希，拒绝未冻结或已修改版本。冻结后没有改参数、参考或判据。
5. 双车同步冻结上一轮预测后各自优化，执行首个控制。当前轮起点与邻车上一轮预测按0.1 s子步对齐，末端用恒速/恒转角零纵向加速度尾段覆盖新时域。双方没有额外让行规则。方向/停止参考模式另外记录为 `reference_motion_allowed`；只有窗口内双方参考允许运动、优化持续接受且都未完成目标时，才检查停滞，不把停止阶段的输入限制算作自愿停滞。

顺序候选通过改变B参考的等待时序取得协调，这是反事实方案本身；没有改变物理输入集合、动力学、碰撞/换挡或终态约束。独立 baseline 的B参考不包含这段等待。参考方向/停止时序属于策略输入，日志和验证报告显式记录，不能把两者说成相同的参考时序。该证据支持车辆模型下的采样可行性，不证明原未协调参考在每次局部求解中都可行。

`two_baseline/`三次均执行15周期（6.0 s），第16轮A两次尝试都返回`Positive directional derivative for linesearch`。第一初始化残差约3.12e-5，也超过1e-5接受容差；移位初始化残差约0.0995。B求解接受，但本离线runner按既定规则不执行任何一方本轮控制，并标记`executed=false`。拒绝前A速度约-0.419 m/s、B速度约0.896 m/s，最小双车加垫间距约4.987 m，实际采样没有超限。

这说明**本基线当前失败类型为优化拒绝，而不是双方连续接受停车解导致停滞**。A已能单独完成任务，排除了“单车本来就不能倒车入库”这个前置缺陷；还不能证明失败是几何无解或无限时间死锁。按照用户提出的顺序，没有在缺少停滞证据时再增加协调策略或调参寻找停滞；ROS接入与同时绕行优化也没有提前扩展。

## 限制与测试

碰撞检查用完整加垫矩形SAT；报告欧氏车身距离时使用矩形边/顶点距离，重叠返回0。每个0.4 s实际执行区间从实际的粗模型状态开始，以0.01 s重新积分采样；不是另一个从起点累积漂移的轨迹。**这些都是采样点验证，不是连续时间安全证明。** 没有几何/动力学无解证明、穷尽搜索或无限时间死锁证明。

单车三次和双车三次都是确定性重复，种子保留为20261010/11/12；不代表扰动下成功率。测量扰动只用于反馈响应单元测试，不改变正式实验初态。

构建通过，全部11/11功能测试入口通过，其中新基线有5项回归：有符号参考/模型一致性、测量反馈响应、非法跨零换挡、目标朝向、尺寸不匹配拒绝。完整构建/CTest输出在 `checks/`。这次没有把上一轮全量静态检查失败宣称通过，也没有为消除项目历史版权/格式问题批量改无关代码。

单车每次每车求解平均约0.31–0.36 s，最大约2.1–2.2 s；双车约0.27–0.28 s，最大约1.25–1.28 s。求解器不能保证0.4 s实时截止；仿真是锁步离线执行。实际逐次值见 `comparison.md`。
