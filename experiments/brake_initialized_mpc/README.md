# 仅修改初始化的新版本：越过6 s，6.4 s仍拒绝求解

**答案：追加动态制动初值解决了原来6.0 s这一轮的拒绝，但没有解决完整双车闭环故障。** 3次确定性双车重复都接受并执行了6.0–6.4 s这一周期，随后在6.4 s因A的全部优化尝试被拒绝停止。两车没有完成目标，也没有复现持续停滞。

本目录是独立版本`brake_initialization_v1`。旧冻结基线、局部诊断、场景和结果原样保留，没有因后续拒绝调参或换地图。

## 只改变什么

`config.json`、A/B参考控制文件与父基线逐字相同。动力学、目标函数、方向/停车时序约束、物理/碰撞限制、输入边界、SLSQP参数及接受规则都不变；没有加入Phase I或松弛量。AST回归测试逐项比较这些函数及原`minimize`调用。

只在原始初值序列后追加三个重试初值：

1. 原有符号控制参考；
2. 原上一轮移位控制（有warm start时）；
3. 最大制动、保持实际转角；
4. 半最大制动、保持实际转角；
5. 最大制动，停车后按原转向速率限制回正。

每次重规划、每辆车都从**该轮实际测得状态**重新生成后三个候选，再用原模型积分；从不加载6秒快照或其中的控制作为运行初值。6秒快照只在回归测试中用于检查已知问题。每轮候选保存`regenerated_from_state`、完整控制和原约束残差，输入合法性逐轮重新检查；“曾经验证过的制动生成方法”不意味着任意后续状态都能生成合法候选。

保留原顺序：前两个初值若已得到接受解，不额外优化制动初值；只有被拒绝才继续尝试。每次SLSQP仍要求`success=true`、有限控制且约束违背≤1e-5，不能因为残差在容差内就忽略失败状态。

`run.py`加载父目录冻结的闭环runner函数，仅将MPC模块替换为本版本。同步预测读取、首控制执行、实际联合碰撞采样、目标与2秒保持、100秒上限和拒绝后停止规则都原样复用。每次启动校验父核心与本版本哈希；版本在首次双车运行前固定于`version.json`。

新增日志只做观测：每次初值、结果控制、求解状态、残差、候选对旧预测的合法性与是否执行都分别记录。没有新增控制权限或改变执行逻辑。

## 实际结果

三次种子20261010/11/12都相同：

| 时刻 | A结果 | B结果 | 实际执行 |
|---|---|---|---|
| 0–6.0 s | 原前两个初值产生接受结果 | 接受 | 与父基线已执行前缀逐元素一致 |
| 6.0 s | 原两初值拒绝；最大制动初值优化成功且约束接受 | 原参考初值接受 | 执行双方**优化所得**首控制，前进至6.4 s |
| 6.4 s | 原两初值和三个制动初值的目标优化都拒绝 | 原参考初值接受 | 全轮不执行，停止离线实验 |

6.0 s并非直接施加制动候选：A优化后的实际第一控制约为`[+0.73487441, -0.09999997]`，执行后状态为

```
[4.005425021248108, -0.41894145787728115,
 0.3971753390661567, -0.1252210578609872,
 -0.09999996839063993]
```

这时重新生成的最大制动初值第一加速度约`+0.31305264`、转角约`-0.1`，与6.0 s生成的`[+1,-0.5]`明显不同，证明不是复用旧快照。由于此时速度较低，最大/半最大制动都在第一周期内停车，两者控制序列相同；仍按预注册次序保留记录。

6.4 s的三种制动候选对A收到的旧邻车预测都满足原约束，最大违背为0。以最大/半最大制动初值优化的结果，最大残差约6.363842e-6，在1e-5容差内，**但SLSQP返回`success=false`、`Positive directional derivative for linesearch`，因此仍拒绝**。停车后回正初值结果约2.763366e-5超容差；原参考/移位初值结果约2.743385e-5/2.427147e-5也超容差。这里既有“残差可接受但优化状态失败”，也有超容差结果，不能把它们都记成优化成功停车解。

每次运行共执行16个控制周期到6.4 s，7次优化尝试拒绝（包括6.0 s的两个和6.4 s的五个）。A/B仍未达目标；最终绝对速度约0.125/0.895 m/s。时限原定100 s，提前停止是原接受规则触发，不是人为截断或为凑停滞调整观察窗口。

已执行区间的最小加垫车身欧氏间距4.526746 m、最小静态SAT间距约0.599659 m、最大实际采样约束违背约7.90e-8，在数值容差内。**这是用双方当轮实际首控制独立计算的0.01 s联合执行检查结果**，不是由A对旧B预测的制动合法性推断的。

全部执行控制都核对为某次被接受优化的`result_controls`，`fallback_controls_executed=0`。6.4 s虽然有合法制动候选，但没有将它作为备用控制执行；B的接受控制也因整轮A拒绝而不执行。

## 初值、优化与备用控制的明确区分

- `braking_initializations.*.feasible_against_old_peer_prediction`只表示完整初值在该轮固定旧邻车预测下通过采样约束，不是优化成功。
- `attempts.*.success/accepted`分别记录求解器状态和原接受规则；结果残差另存，即使合法结果也可因求解状态失败被拒绝。
- `solver.accepted`只表示本轮最终采用的优化结果被接受。
- `executed`、`actual_violations`及`min_sampled_pair_body_distance_m`只记录双方实际应用首控制后的联合验证。
- `joint_current_execution_safety_certified=false`明确保留在每个制动候选诊断中。候选对旧预测合法不保证另一车采用当前新控制时也安全。
- 本版本没有备用控制策略，所有`fallback_executed`为false。若以后做备用制动研究，应独立配置，并区分接受的优化控制、备用控制和双方联合执行验证；不能事后把本轮拒绝改成成功。

## 交付与验证

`results/two_SEED.jsonl`保存每轮双方完整输入/输出、三个动态候选、所有求解尝试与真实执行；`all_optimization_rejections.jsonl`列出全部21次拒绝（每次运行7次），可按种子/时刻/车辆/初值查看。`rejected_problem_SEED_car_0.json`保存6.4 s A的下一局部问题；car_1文件是同轮**未执行的B问题**，B优化本身并未拒绝。CSV包含目标距离、朝向、速度/方向、位移、尝试次数、实际间距、执行标记。对照表与时间序列图比较父基线停在6 s与新版本停在6.4 s。

构建成功，13/13功能测试入口通过，新版本4个回归覆盖：只改变初始化的AST/文件一致性、按实际状态生成正倒车制动、合法候选不能覆盖求解拒绝、6秒原问题不经Phase I恢复接受解。完整实际输出在`checks/`。没有宣称项目历史全量版权/格式静态检查已通过。

求解耗时每车平均约0.31–0.32 s、最大约1.53–1.59 s，具体重复值见对照表；继承计时主要覆盖优化尝试，不包含新增初值生成前检查的全部耗时。仍是离线锁步仿真，不保证0.4秒实时截止。所有安全性记录仍限于采样点，不是连续时间证明。

已验证事实：仅增加初值恢复了6秒这一轮，3次重复都越过6秒；6.4秒拒绝仍存在，且该轮合法制动候选可构造。未取得证据：双车完成任务、持续接受停车解导致停滞，或备用控制下的任务完成。不能归为场景无解或MPC策略性死锁。
