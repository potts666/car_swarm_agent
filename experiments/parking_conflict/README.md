## 实际工程审计与冻结

仓库 HEAD：`2d5f84f225899ae4b749cb2c851bfdbed86a9642`。工作区原先已有未提交修改；不能仅用 HEAD 重建 baseline。`baseline_manifest.json` 保存修改清单及原始文件 SHA256；`frozen/` 是当时实际使用的 Python MPC 与碰撞辅助函数的逐字副本。原文件 `test/decentralized_mpc.py`、`test/optimize_spatial_temporal.py` 未修改，已核对哈希。

实际系统分为以下入口，不能混为一谈：

| 入口 | 实际功能 |
|---|---|
| `agent_node` / `planner_demo.launch.py` | Hybrid A* 空间规划，发布地图及路径，非双车 MPC |
| `trajectory_comm_node` / `two_car_comm.launch.py` | 两辆车共享 map，发布自定义预测消息、接收对方并显示路径；1 Hz 重发事先规划轨迹，非执行 MPC |
| `yield_demo_node` / `yield_demo.launch.py` | Hybrid A*、S-T 让行与连续轨迹检查；可播放或先做单车离线反馈跟踪再播放；对方轨迹预设，非双车 MPC |
| `test/decentralized_mpc.py` | 两个独立优化问题读取上一轮预测，同步执行第一控制量，真实离散模型离线闭环 |
| `test/ros_decentralized_mpc.py` | 两个独立 rclpy MPC 进程通过 ROS 2 交换预测，锁步离线 plant；不是实际车辆执行器接口 |
| 本目录 `experiment.py` | 冻结 Python MPC 的停车场景离线闭环、固定时序反事实与显式循环规则对照 |

已运行原 ROS 多进程入口的 0.8 s 启动检查，日志在 `results/ros_original_smoke/`；它仍使用原交叉场景，不作为停车证据。停车实验没有接入 ROS 2 topic 或实车控制。缺少的是**支持倒车的原 MPC 输入集合、停车任务的双车 ROS 场景接入和实际执行器**，而不是假定所有 MPC 均不存在。

模型审计：

- 配置车长 4.5 m、宽 1.8 m、后悬 1.0 m、轴距 2.7 m；后轴中心为位姿原点。车身中心前移 1.25 m，四边各加垫 0.1 m，验证用 4.7 × 2.0 m 矩形。这是工程配置尺寸，未进行实车测量。
- 转角 ±0.5 rad，最小后轴转弯半径 2.7/tan(0.5)=4.94231685 m。Hybrid A* 可倒车；Python baseline **不可倒车**，速度限制 0–1 m/s。C++ 跟踪模型允许有符号速度，换挡先停车；不能用它冒充 Python MPC。
- Python plant：中点自行车积分，状态 `[x,y,yaw,v,steering]`，输入每步 `[acceleration,steering]`；控制步长 0.4 s，4 个积分子步，12 步预测即 4.8 s。输出 12 个控制量及求解状态；执行仅第一控制，随后再次规划。恒速/恒转角尾段覆盖下一轮预测时域。
- 加速度 ±1 m/s²、转角变化率 ≤1 rad/s、纵横向合加速度 ≤2 m/s²。预测约束检查每 0.1 s 一次，邻车 SAT 分离间距 ≥0.08 m，静态 SAT ≥0.03 m；都使用加垫车身。
- Python `solve`：SLSQP、3-point 数值导数、80 次迭代、ftol=1e-5；先用移位 warm start，失败再以制动初值重试，success 且约束违背 ≤1e-5 才接受。目标权重位置3、朝向2、速度1、控制0.05、控制变化0.15、末端位置8；原函数完整冻结。
- 原闭环目标：距离 <0.3 m、速度 <0.05 m/s，**未检查朝向**。本实验统一增加朝向 ≤10°，不会修改原求解器。
- 离线预测交换：冻结两份上一轮 packet，再分别优化，时间原点100 s；无 Gauss-Seidel 协调。ROS 版本用 `/mpc_benchmark_PID/car_i/prediction` 的 `PredictedTrajectory`，请求/控制用 String；可靠、transient-local、depth10，最大消息龄0.45 s，异常或求解失败时显式制动。离线 baseline 则拒绝后直接停止执行，保留此区别。
- C++ 空间碰撞：加垫矩形 SAT，空间采样0.1 m；原动态碰撞器默认0.1 s，线性位置/最短角度插值。S-T 默认速度网格时间步0.5 s，另有连续轨迹及验证代码。本停车实验不调用 S-T，不声称复现其连续检查。
- 原 C++ 跟踪使用0.01 s 数值步、转向限速、步内圆弧积分，与 Python 中点模型不同。Python 本实验以0.01 s 密集重积分作采样验证；不是连续时间证明，也不能忽略不同积分分辨率的数值误差。

## 冻结场景与结果判据

全部坐标以米、角度以弧度记于 `scenario.json`。A 从 `(6,0,0)` 倒至 `(-1.460262002187406,-3.4,0)`；B 从 `(-10,0,0)` 到 `(14,0,0)`。两车初速、转角均为0。道路上边 y=5.5，下边通常 y=-1.6，x∈[-5,10] 处有路侧开口；车位 x∈[-3.5,3]、y∈[-4.7,-1.6]。障碍矩形和车位多边形及其确切数值保存在配置中，矩形顶点由 `[x,y,w,h]` 唯一决定。另外继承碰撞辅助函数的 ±30 m 外边界。

几何先按车身/转弯半径确定，再冻结；没有根据 baseline 调整地图或限值。反事实生成器的首次预检违反加速度限制，已保存在 `preflight_rejected/`，其 baseline 尝试被中止、不是正式证据；修正的是输入加减速斜坡，地图、目标和约束未变。绕行失败未通过改地图修饰。配置种子20261010、20261011、20261012，baseline 重复3次。SLSQP 没有随机采样，这些是确定性重复验证，不代表随机扰动鲁棒性。

运行前固定：目标位置0.3 m、朝向10°、速度0.05 m/s；观察24 s，每0.4 s 重规划。持续停滞窗口8 s，双方均未到达，各车相对窗口首状态最大位移 <0.1 m，目标距离减少 <0.1 m；只有期间全部执行的规划可接受，且双方许可开放，才归为实验中的持续停滞。规则循环等待使用独立规则配置：A 必须等 B 到目标，B 必须等 A 到目标。固定初始双方未到目标，双方许可始终为 false；日志记录清晰等待环，不归咎于 MPC。

正常等待须最终两车到目标且等待期间另一车推进。求解拒绝/超时/搜索失败只算未找到可行解。本实验没有几何不可行性证明、没有穷尽离散状态搜索，不能产生“场景无解”证明，更没有无限时间死锁证明。

反事实控制序列有独立完整时域：等待策略55.2 s、绕行67.2 s；这是完整任务验证，与 baseline 预定24 s 停滞观察不同，不拿24 s截断反事实。时序仅按原语构造，不追求最短完成时间。

## 验证证据与策略比较

`results/scene.png` 标明障碍、车位、起终点和 A 的加垫完整车身扫掠；红色矩形并非仅后轴路径。`uncoordinated_conflict_validation.json` 在相同时序的 A 倒车/B 直行中检测到车身相交（最小 SAT=-2.606858 m），证明该候选确实冲突，不证明场景无解。

每个候选保存完整控制序列、两车带时间的 CSV、验证 JSON。验证覆盖静态/双车车身、速度、加速度、转角、转角速率、合加速度、换挡过零、最终位置/朝向/速度。距离用 `body_distance` 的矩形边/顶点欧氏距离；重叠返回0。两车安全约束用 SAT 分离间距下界，实际欧氏间距另报。所有最小值只针对0.01 s采样；**不报告最小连续时间间距**。还需要区间包络、经过证明的 Lipschitz 界或其他连续检测，才能排除采样之间碰撞。

| 策略/证据 | 成功 | 完成时间 A/B | 最小加垫车身间距 | 倒车进入次数 A/B | 实际判断 |
|---|---|---|---|---|---|
| 原 baseline，3次 | 0/3 | 均未完成 | SAT下界1.809 m | 0/0 | 12 s拒绝求解；未复现双车停滞 |
| 规则等待环，1次 | 0/1 | 均未完成 | 11.300 m | 0/0 | 24 s规则循环等待，双方始终无许可 |
| B等A先入库，固定时序控制 | 1/1 | 24.66/54.34 s | 1.400 m | 1/0 | 物理有符号速度限制下正常等待，采样验证通过 |
| B绕行、A同时入库，固定时序控制 | 0/1 | 候选目标命中24.66/66.26 s | 4.800 m | 1/0 | 静态边界碰撞，整个候选拒绝，不能称完成 |

**后两行是独立的时序协调策略，通过相同自行车 plant 执行完整开环控制，不是新增 MPC。** 两者使用车辆物理速度集合[-1,1]，原 baseline 使用[0,1]。除此以外采用相同初态、地图、尺寸、间距和输入限制。验证明确分别输出 `physical_envelope_pass` 和 `unchanged_baseline_envelope_pass`。两条倒车候选对后者都为 false，不能满足严格“相同 baseline 限制”的证据 A。原 baseline 的限制原样保留，没有悄悄打开倒车。

baseline 平均/最大每车求解耗时分别为0.506/4.133、0.516/4.117、0.489/3.994 s；均超过0.4 s控制周期的实际轮次日志可查。本实验按仿真时间锁步，没有实时性能保证。规则拒绝无需求解；固定时序候选无需优化器，不把轨迹验证耗时混成 MPC 求解耗时。策略完整表在 `results/comparison.md`，机器可读表在 `comparison.json`。

证据 B：每次均执行30个周期，第31轮在t=12 s拒绝 A 优化，原因 `Positive directional derivative for linesearch`。日志保存两次优化尝试、违反约束量、预测、邻车输入、参考输入、warm start、控制、许可、真实下一状态、位移及车身间距；拒绝轮明确 `executed=false`，未偷偷制动或继续执行。A几乎不动，但 B 每周期前进约0.36 m；不能把 A 的单车未进展当作双车停滞。`baseline_series.png` 和各次 `_metrics.csv` 显示时间序列，CSV间距按每个实际执行区间重积分采样求得。

结论分类：

- 已验证事实：配置车辆下等待候选满足采样点的物理限制和终态；未协调候选车身冲突；绕行候选违反静态限制；原 MPC 未改动且无法输出合法负速度；三次在相同周期求解拒绝；独立规则对照存在明确等待环。
- 未找到证据：严格相同 baseline 输入限制下的倒车可行解；当前固定场景的双车 baseline 持续停滞；通过验证的同时绕行候选。不能写“场景有解但 baseline 死锁”的结论。
- 仍需证明：连续时间安全、几何/动力学无解、无限时间死锁、闭环协调策略的鲁棒性。要研究可倒车的 MPC 停滞，下一实验须另立有符号速度 MPC 配置并重新预注册；本次没有替换 baseline 或调整标签。

## 复现

依赖 Python 3.12、numpy1.26.4、scipy1.11.4、matplotlib，以及现有 ROS 2 Jazzy/colcon 构建环境；具体来源哈希/参数见 `execution_manifest.json`。离线实验不需要 DDS 或 RViz。

```bash
cd /home/sunflower/car_swarm_ws
source /opt/ros/jazzy/setup.bash
colcon build --packages-select car_swarm_agent --cmake-args -DBUILD_TESTING=ON
source install/setup.bash
python3 src/car_swarm_agent/experiments/parking_conflict/experiment.py --output /tmp/parking_replay
python3 src/car_swarm_agent/experiments/parking_conflict/summarize.py --output /tmp/parking_replay
ctest --test-dir build/car_swarm_agent -R '^test_' --output-on-failure
```

实验命令成功退出表示资料生成完毕，**不表示所有策略成功**；必须读取验证与分类字段。所有候选检查完才运行baseline，没有通过测试的候选仍保留失败记录。重新执行默认输出会覆盖同名记录，上述命令使用独立输出目录保护交付基线。

已实际构建成功，10/10功能测试入口通过，包括本实验4个测试（等待物理/原限制区别、真实车身冲突、绕行失败、目标朝向）。全量 `colcon test` 的静态检查失败：copyright、cpplint、flake8、lint_cmake、uncrustify；新实验 Python 也有版权/格式检查问题，冻结副本保留原格式。完整失败清单在 `results/checks/parking_test_results.txt`，不宣称全套测试通过，也未为消除旧 lint 问题批量修改无关代码。
