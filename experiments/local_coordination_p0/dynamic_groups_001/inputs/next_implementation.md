# 区域预约：从解析证书到工程控制的最小接入

本任务在用户准备进入代码阶段时交给Ubuntu Codex。先复现随包两份标准库检查，再实施。原C0_fix_002、原论文与历史日志保持原样；新结果存入独立`region_reservation_001/`。

## 1. 导出实际有理ZOH控制

从`theory.md`读取明确的等待中心、资源R、进入/出口域、7类空间连接及时间配置。alpha=acos(3/4)、delta_c=atan(0.45)、D_s=3sqrt(7)已有区间界；先将每段速度、轮角和输入导出为工程使用的有理数。

每段保持原h=0.2s，速度爬升与制动由有理输入保证末端v精确归零；停车转轮保证delta精确到新目标。圆弧采用工程有理轮角后，按实际曲率重新积分并认证，保存相对解析路径的偏差。

输入量化误差加入原0.05m车身管。先检查剩余误差额度，再生成实际接收盒；如需收紧入口域或增加保守拍数，报告具体推导并更新所有预算。物理净空要求保持0.5m。

## 2. 先复核实际域衔接

分别认证W_in→W_hold→G_in→G_out→目标。保存实际控制、连续矩形车身管、适用域、模型和版本。对每拍终端继续使用已认证流像与后续控制，补齐32拍局部问题所需导数和接收行。

先得到实际输入与后续证书，再调用局部SOCP提出新候选。新提案拒绝时继承已认可真实尾段；来源、权限、接收/K、预算按C0_fix_002逐事件绑定。

## 3. 增加单资源预约协议

在同一提交context加入resource_id、owner、源快照、证书ID、进入/释放条件与后续。进入前持权，驶出后经完整联合检查释放。优先规则保留为可替换的选择函数；选择对象为未完成且有合法提案的车，有限轮协商失败则执行已有完成策略。

新owner开始准备时，前车的出口尾段继续作为同一联合版本的有效局部计划。分开记录资源占用权与区域外出口动作权限，执行端仍核对四份计划及同一提交编号。

首次验证使用一条具体在线选择轨迹，记录选择依据，不将它写成全方法的固定车序。理论覆盖其它顺序的依据是逐车对等待/完成上下文的证书。

## 4. 验证两车重叠连接

前车到G_out后，执行其停车尾段；后车开始等待至G_in的准备。复核名义95拍尾段与101拍准备，以及所有实际偏差。额外记录同侧纵向分离条件；若实际有理控制改变这些时长，重新认证时序。

最小控制回放先覆盖一例相反方向交接和一例同方向交接，分别包含合法受理、版本损坏拒绝、旧策略续行与完整联合验收。四车原始准备可同时进行，其车道分离独立验收。

## 5. 验收与报告

分别报告解析检查、有理输入认证、协议接入、控制重放、局部SOCP更新五层结果。实际任务时间、计算墙钟、逻辑采样周期分别计量。
