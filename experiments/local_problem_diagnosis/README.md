## 车辆硬约束与任务时序审计

必须满足的车辆/安全约束是自行车动力学、有符号速度界、加速度、转角、转角变化率、合加速度、静态与邻车预测间距，以及真实换挡必须过零。**整个任务的目标位置/朝向/停车速度是闭环验收条件；此局部函数没有强制4.8 s末端到目标的硬等式**，只有末端位置代价。

当前求解器另外把参考方向和固定停车周期当作硬约束；它们是策略施加的限制，不是车辆本身的物理要求。位置/朝向/有符号速度及参考输入追踪则是软代价，可以牺牲进度换取安全。

本轮12个方向模式全部为-1，即v≤0；**v=0合法**。本轮没有停车等式，所以当前6 s失败不能归因于“固定停车等式直接禁止等待”。也没有尝试通过允许前进来放宽这个问题；合法候选完全满足原倒车方向约束。

整条A参考则规定：0–0.8 s停车设置转角；0.8–12 s倒车；12–13.6 s停车换转角；13.6–24.8 s倒车；24.8 s以后停止。换段前及停止阶段的速度端点等式强制固定时序。尤其参考耗尽后，`window()`一直给gear=0、零参考控制；若车辆尚未到目标但已经停住，每步末端速度为0会迫使纵向加速度为0，从而不能追赶漏掉的目标。这是潜在的**任务时序锁定**，应与车辆不可行、优化失败或自愿停滞区分。

`full_reference_policy_audit.json`保存完整方向时段和强制停车时刻。顺序反事实是通过改变B计划等待时序成功，它证明相同物理限制下的采样可行性；不能证明未协调参考的每个局部问题都可行，也不意味着参考停车时序必须当作不可调整的物理约束。
