# 完整退出、实际通过与通行权释放协议

入口 `scripts/run_pass_release.py`。这是离线完整闭环模拟预演，继续使用八个安全静止初值、已验证的 OSQP 等价缩放形式和独立分项验收。原复现、四组对照、退出筛选入口及历史报告均保留。本轮不实现退让车回归，不标记双方任务完成。

## 几何与停驻目标

直接复用 `make_scene()` 生成的 `channel`、`road`、`road.bays`、`retreat_x` 和 `goals_x`，没有为通过实验修改边界或车辆位置。

|量|本轮定义|
|---|---|
|单通道|20 m 时 x∈[−10,10]；28 m 时 x∈[−14,14]，y∈[−1.4,1.4] m|
|保护区域 R|上述单通道主路矩形，包括整个通道内部；不包括入口外退让区|
|A 正向退出边界|R.xmax|
|B 反向退出边界|R.xmin|
|释放裕度|0.5 m，配置字段 `release_margin_m`|
|通过后目标|原有 `goals_x`：A x=+21.75/+25.75 m，B x=−21.75/−25.75 m；y=0|
|目标到达阈值|位置误差≤0.08 m、绝对纵向速度≤0.025 m/s|
|全车离开|A：x−2.35≥R.xmax+0.5；B：x+2.35≤R.xmin−0.5|
|目标几何验收|目标处全车身道路容纳，且整车满足离开 R 的条件；不满足则 `geometry_insufficient`，不得扩大地图|

道路纵向范围原为 ±28.8/±32.8 m。目标中心处车身最外缘为 ±24.1/±28.1 m，能在原道路内停车。退让区中心位于通道边界外4.7 m、y=3 m；真实停驻位置以 EXIT 积分日志为准。

## 阶段与状态继承

`EXIT → PARKED_READY → PASS → CLEARED_HOLD → RELEASED`，任何必要验收失败或超时进入 `FAILED`。角色保持不变，通行权持有者是原等待车。

先从同一初值分别生成两条完整 EXIT 候选，再执行原有 `select_baselines()`：固定 A 选 A；筛选只在完整退出通过者中按退让距离选择。选角结果在任何 PASS 模拟前写入 `selection.json`。不查看后续通过结果，不在失败后改选另一角色。

两个基线的 EXIT 前缀复用所选候选的原始执行日志；后续分别独立继续模拟。读取的是 CSV 最后实际积分的 x/v/y 和全局时间，上一加速度读取实际控制列；warm start 来自最后一次执行求解的控制序列移位。横向日程从已执行 enter_bay 开始时刻恢复，保持原日程的时间戳和持续时间，不把横向状态换成理想点。没有将最后速度直接改零，没有重置时间或移动任何车辆。复用已生成的 EXIT 前缀是离线分支模拟，不是现场重复执行两次退出。

PARKED_READY 重新确认完整退出验收、车身在退让区、横向日程结束、退让位置/速度阈值、等待车原位误差≤0.01 m及速度≤0.01 m/s、两车道路容纳和车身间隙。授权前后记录 x/v/y、时间、上一加速度、warm controls 和横向日程的连续性；位置、速度、加速度、时间分别记录残差，不混合单位。

PASS 中退让车以自身实际 EXIT 终态 x 为保持参考，y 继续沿原已完成日程保持，仍实际求解并积分。相对实际参考的位置偏差≤0.01 m、速度差≤0.025 m/s、横向偏差≤1e−5 m；同时绝对速度≤0.025 m/s。车身仍须位于自己的退让区，并完整保持在主路横向范围之外。通过车目标仅更新为原有通过后目标，无新增预测末端目标位置硬约束。

## 每周期检查

保持控制周期0.4 s、预测6.4 s、子步0.1 s。各次 OSQP 最多20000次ADMM迭代，eps_abs/eps_rel=1e−8；无诊断求解、无失败重试。

1. 主返回控制通过 `audit_controls()` 独立逐子步积分和分项检查：数值有限、动力学、速度、加速度、预测末端速度、道路纵向、邻车、目标不越界。各物理量单列，局部容差1e−5，继承既有规则。
2. 64个预测样本全部进行两车配对验收：有限值、道路并集的全车身容纳、速度/加速度、车身间隙≥0.5−1e−5 m，以及退让车完整停驻保持。
3. 对即将执行的0.4 s段精确积分，检查全部0.1 s子步、独立动力学残差和相同道路/间距/停驻条件。CLEARED_HOLD 还要求该段每个样本均实际整车离开 R、位于通过目标容差内且满足低速阈值。整段验收失败则中止离线分支，不提交该段状态，`applied_to_simulation=false`。
4. 仅提交已通过验收的积分状态，检查当前阶段完成与释放条件。

退让车先针对通过车上一预测求解，通过车针对本轮退让车预测求解；首轮邻车预测由已继承的 warm controls 延拓生成。纵向前后约束按横向占用重叠逐样本掩码，阈值为车宽+安全裕度=2.5 m，掩码记录于每次求解。当前 PASS 中两车横向距离3 m，因几何不重叠而纵向约束不激活；这是原有掩码规则的结果，不是人为关闭安全约束。外部配对车身检查始终生效。

## 实际清空、停驻确认与释放

首次实际整车清空时间来自已提交执行段中的第一个满足车尾清空的样本，不使用未来预测替代。中心越过边界但车尾未清空时仍不满足条件。

实际整车离开 R、到达目标且低速、退让车保持停驻、当前车身安全、最新预测通过且未来不再占用 R、持有者匹配时，进入 CLEARED_HOLD，记录 `first_stop_candidate_time_s`。继续同一控制器和目标，所有保持条件连续满足0.8 s后才记录 `stopped_confirmation_time_s` 和释放时间。本轮该确认与 RELEASED 同时发生；首次进入阈值不是确认成功。

保持期间任何必要检查失败，整次策略失败，不重新计时或改选角色。release 事件记录持有者、两车实际状态、释放检查与 R 的范围。释放只终止本轮 R 的占用，不启动退让车回归。`both_tasks_completed` 始终 false。

## 失败、统计与证据

EXIT、PASS（含CLEARED_HOLD）、总模拟时间上限分别100、100、200 s；新段将超过上限时不再执行。失败区分局部返回验收、配对预测、执行段、退让保持、清空保持和阶段/总超时。FAILED 只表示离线模拟中止，不表示物理安全停车已验证。

每个策略目录有全链 actual.csv、predictions.jsonl、solves.json、path_checks.json、events.jsonl 和 summary.json。拒绝段日志与已提交执行日志明确区分，`minimum_executed_gap_m` 仅取已提交状态，`minimum_predicted_gap_m` 单列全部受检预测；不混合。非有限返回值在诊断JSON中以null留痕，绝不执行。

阶段耗时均为模拟时间；候选生成、选角等待及各阶段计算单列墙钟时间。两条 EXIT 的公共生成开销与分支的归属 EXIT 开销不是可累加的独立运行成本。固定角色实际部署可以省去另一候选，当前共享成本只用于离线公平对照。没有实时deadline中断或在线等待补偿，不把计算与模拟时间相加成部署恢复时间。

`verify_pass_release.py` 独立读日志核验实际动力学、采样间距、状态/控制器继承、完整车身清空时间、释放证据、选角只依赖退出结果和同角色轨迹一致性。所有结论限于本组初值、当前无偏航轴对齐模型和离散检查，未证明连续时间安全、转向可达性、递归可行性或双方任务完成。

## 保持硬约束补齐版本

`--hold-constraints` 启用新模式；不开启时保持旧默认行为。模型、0.4 s周期、6.4 s预测、0.1 s采样、进入条件、原0.025 m/s速度阈值、目标±0.08 m区间及0.8 s确认时长均不变。

新模式只在通行车的CLEARED_HOLD优化中增加全预测速度±0.025 m/s和目标位置±0.08 m线性硬约束。其他道路、加速度、邻车、目标不越界和末端零速度均保留。QP局部新增hold_speed_m_s与hold_position_m分项残差；外部保持检查仍使用原严格阈值，不借用QP残差容差放宽阈值。

切换前先从当前实际状态做两车配对保持QP诊断，并检查完整预测和清空；不修改位置、速度、时间、上一控制或warm start。失败即终止PASS，不宣称进入CLEARED_HOLD，不重置计时延后补救。成功则按原进入时刻开始0.8 s确认，实际执行仍重新求解、积分并外部验收。

另保存通行车首段u=−v0/dt、后续零加速度的制动序列，进行独立局部、目标不越界、保持区间、道路、邻车、配对完整路径及清空检查。该序列是诊断证据，不是替代控制。每次进入前两次额外QP诊断独立计数，计算耗时计入PASS；制动序列检查不额外调用求解器。日志为hold_prechecks.json，不修改历史日志或报告。
